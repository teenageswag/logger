# Plan: Refactor & Enhance C++23 Logger

## Current State

Single-header async logger (`logger.h`, 536 lines) with:
- Ring buffer (4096 entries) + background worker thread
- Two sinks: `ConsoleSink` (ANSI colors) and `FileSink` (size-based rotation)
- Compile-time filtering via `LOG_ACTIVE_LEVEL` + runtime filtering via `set_level()`
- `std::format` + `std::source_location` integration
- Macro-free API via `struct log` with static methods

## User Decisions

- **Split files**, but keep single `logger.h` entry point (include umbrella)
- **Windows-only** (no POSIX/Linux/macOS)
- **Priority features**: JSON Sink + Structured Logging (kv pairs)
- **Overflow policy**: drop oldest messages (non-blocking)

---

## Part A: Bug Fixes & Correctness

### A1. Double level check in log methods
Each `log::trace/debug/info/warn/error` checks both `if constexpr` AND runtime `if (Level::X < get_level())`. The runtime check is redundant — `log_impl()` already does it.

**Fix**: Remove the duplicate runtime check from the 5 methods in `struct log`. Keep only `if constexpr`.

### A2. Thread safety of `min_level_`
`min_level_` is read/written from multiple threads without synchronization.

**Fix**: Change `Level min_level_` to `std::atomic<Level> min_level_` in `Logger`.

### A3. Ring buffer overflow — drop oldest (non-blocking)
Currently `enqueue()` blocks when full. Change to non-blocking: overwrite oldest entry when buffer is full.

**Changes**:
- `enqueue()`: remove `cv_push_.wait()`, instead overwrite `queue_[head_]` and advance `head_`
- Add `std::atomic<size_t> dropped_count_` for diagnostics
- Worker loop: when consuming, if `dropped_count_ > 0`, optionally log a warning about dropped messages

### A4. FileSink rotation — only 1 backup
Currently creates only `.1`. Add `max_files` parameter to rotate through `.1` to `.N`.

**Changes**:
- `FileSink` constructor: add `size_t max_files = 1` parameter
- `rotate()`: shift `.N-1` → `.N`, `.N-2` → `.N-1`, ..., `.1` → `.2`, current → `.1`

### A5. FileSink — periodic flush
Currently flushes only on ERROR or shutdown. Add configurable flush interval.

**Changes**:
- Add `std::chrono::milliseconds flush_interval_` parameter (default: 1000ms)
- Worker thread: track last flush time, flush if interval elapsed

### A6. `ConsoleSink` resource leak
`freopen_s` opens handles that are never closed. Store `FILE*` handles and close in destructor.

## Part B: File Structure Refactor

Keep a single `logger.h` umbrella header, but split implementation:

```
logger/
  src/
    logger/
      logger.h              — public API umbrella (includes everything)
      core/
        types.h             — Level enum, LogMessage struct
        logger.h            — Logger class declaration
        logger.cpp          — Logger implementation (thread loop, queue, ring buffer)
      sinks/
        sink.h              — Sink base class
        console_sink.h      — ConsoleSink + ConsoleSinkConfig
        console_sink.cpp
        file_sink.h         — FileSink
        file_sink.cpp
        json_sink.h         — NEW: JSON output sink
        json_sink.cpp
    example/
      main.cpp
```

**Key constraint**: User only needs `#include "logger/logger.h"` — the umbrella header pulls everything.

### B1. Extract `LogMessage` with structured fields
Extend `LogMessage` to support kv pairs:
```cpp
struct LogMessage {
    Level level;
    std::chrono::system_clock::time_point time;
    uint32_t thread_id;
    std::source_location loc;
    std::string text;
    std::vector<std::pair<std::string, std::string>> kv_pairs;  // NEW
};
```

### B2. Extract formatting
Both `ConsoleSink::write()` and `FileSink::write()` duplicate the timestamp + source-location formatting. Extract to a `format_common.h` utility.

## Part C: New Features (Priority)

### C1. Structured Logging (kv pairs)
Allow attaching key-value pairs to log messages:
```cpp
log::info("User logged in", log::kv{"user_id", 42}, log::kv{"ip", "192.168.1.1"});
log::error("DB connection failed", log::kv{"host", db_host}, log::kv{"port", 5432});
```

**Implementation**:
- Define `log::kv` struct: `struct kv { std::string key; std::string value; template<typename T> kv(std::string k, T v) : key(std::move(k)), value(std::format("{}", v)) {} }`
- Add variadic overloads to `log::trace/debug/info/warn/error` that accept kv pairs after the format string
- `LogMessage::kv_pairs` stores them
- Console sink: append `[key=value]` after the message text
- JSON sink: serialize as flat fields

**New file**: `core/kv.h` (kv struct + helper)

### C2. JSON Sink
Output logs as JSON lines (one JSON object per line):
```json
{"timestamp":"2026-07-06T12:00:00.123","level":"INFO","file":"main.cpp","line":42,"thread":1234,"message":"User logged in","user_id":42,"ip":"192.168.1.1"}
```

**Implementation**:
- `JsonSink` inherits `Sink`
- `write()` produces one JSON line per log message
- Structured kv pairs become top-level JSON fields
- Output to file (inherits from `FileSink` approach) or stdout
- Config: `JsonSinkConfig { path, max_size, max_files }`

**New files**: `sinks/json_sink.h`, `sinks/json_sink.cpp`

### C3. Expose Logger instance for custom sinks
Add `log::instance()` static method returning `Logger&` so users can create custom `Sink` subclasses:
```cpp
class MySink : public log::Sink {
    void write(const log::LogMessage& msg) override { ... }
    void flush() override { ... }
};
log::instance().add_sink(std::make_unique<MySink>());
```

## Part D: Additional Improvements

### D1. `std::jthread` + `std::stop_token`
Replace raw `std::thread` + `bool stop_` with `std::jthread` for automatic cooperative cancellation.

### D2. Thread name registration
```cpp
log::set_thread_name("WorkerPool-1");
```
Stored in thread-local string, included in log output.

### D3. ConsoleSink — improved color scheme
Current colors are good, but consider:
- Add bold/bright variants for ERROR
- Reset color properly on Windows (currently works, but verify with long messages)

### D4. CMake build system
Add `CMakeLists.txt` at project root for building the example and (eventually) tests.

### D5. Unit tests
Add a `tests/` directory with basic tests:
- Level filtering
- Ring buffer overflow (verify drop-oldest behavior)
- File rotation
- JSON output validity
- Structured kv formatting
